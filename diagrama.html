📈 Diagrama de Flujo y Arquitectura de Datos

Este documento describe el flujo completo y la arquitectura de la base de datos de la aplicación. Está diseñado para ser una guía clara y escalable, permitiendo a cualquier persona comprender cómo interactúan los diferentes componentes del sistema, desde la configuración inicial de una empresa hasta la generación de reportes diarios.

Módulo 1: Configuración Central y Entidades Principales (El Núcleo)

Todo comienza aquí. Este es el corazón del sistema multi-tenant. Una Company es la entidad raíz que agrupa toda la información. Cada compañía puede tener múltiples Locations (sucursales), y a su vez, múltiples Users con diferentes roles. Las tablas Company Settings y Payment Methods permiten una alta personalización para cada negocio.

Escalabilidad: La separación por company_id en casi todas las tablas es la clave para un modelo SaaS (Software as a Service), permitiendo que miles de negocios coexistan en la misma base de datos de forma segura y aislada.

Módulo 2: Gestión de Operaciones y Menú (El Inventario)

Este módulo define lo que un negocio vende y cómo está organizado su espacio físico. Una Company define sus Categories (Ej: Bebidas, Entradas) y dentro de ellas, sus Products. También se configuran las Tables y Cash Registers (cajas registradoras) disponibles en cada Location.

Escalabilidad: Al desacoplar productos y categorías del resto del sistema, es fácil implementar futuras funcionalidades como gestión de inventario, combos, o modificadores de productos sin alterar el flujo de órdenes.

Módulo 3: Flujo de Órdenes y Pagos (El Corazón de la Operación)

Este es el flujo principal y más dinámico. Un User (mesero) crea una Order asociada a una Table. La orden contiene múltiples Order Items, que son los Products solicitados. El estado de la orden (status) y de cada item (kitchen_status) cambia a lo largo del proceso. Finalmente, la orden se paga a través de uno o más Order Payments.

Escalabilidad: La separación de `orders`, `order_items` y `order_payments` permite manejar escenarios complejos como cuentas divididas, pagos parciales con diferentes métodos y envío de items a cocina en momentos distintos.

Módulo 4: Gestión de Caja (El Flujo de Dinero)

Este flujo es crucial para el control financiero. Un User (cajero) inicia una Cash Register Session al comenzar su turno, registrando un saldo de apertura. Cada pago en efectivo (y otros movimientos) se registra como un Cash Movement dentro de esa sesión. Cuando se realiza un Order Payment en efectivo, éste se vincula a la sesión de caja activa y genera su correspondiente movimiento de dinero.

Escalabilidad: Este modelo permite auditorías precisas, manejo de múltiples cajeros en una misma caja (en turnos distintos) y la fácil incorporación de otros tipos de movimientos de dinero (depósitos, retiros, gastos).

Módulo 5: Auditoría, Reportes y Notificaciones (La Inteligencia de Negocio)

Estas tablas no participan en el flujo de venta en tiempo real, pero son vitales para la auditoría, el análisis y la comunicación. Activity Logs registra acciones importantes de los usuarios. Order Status History guarda cada cambio de estado de una orden. Daily Summaries pre-calcula métricas clave para reportes rápidos y eficientes. Finalmente, Notifications permite enviar mensajes a los usuarios.

Escalabilidad: La tabla `daily_summaries` es una técnica de optimización clave. Evita tener que calcular métricas pesadas sobre la tabla de órdenes cada vez que se consulta un reporte, lo que garantiza que el sistema siga siendo rápido incluso con millones de órdenes.
